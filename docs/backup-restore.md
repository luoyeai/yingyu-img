# 备份与恢复

备份必须同时包含数据库、图片文件和配置。只备份 `public/media` 不能恢复图片库分组、原始名称、处理参数、停用状态或私有原图。只备份数据库不能恢复文件。APP_KEY 灾备缺失会使加密的云存储密钥无法解密，不得为恢复系统重新生成 APP_KEY。

## 备份范围

- **数据库**：项目 MySQL 库全部表；包含管理员密码哈希、图片元数据/相对路径、分组、设置和回收站时间。
- **公开图片**：本地 `public/media/`（完整年月目录），以及各云配置对应桶与前缀下的公开 WebP。云端对象须按同一维护窗口独立备份或复制到受保护灾备存储；本站预览不能替代完整云图。
- **私有文件**：`storage/app/previews/`、`storage/app/originals/`、`storage/app/disabled/`，以及应用实际使用的其他持久文件目录；临时处理中间文件无需长期保留。
- **配置**：`.env`（特别是原 `APP_KEY` 及轮换需要的旧密钥、DB/URL/安全设置）、已部署源码或版本标识、`composer.lock`、Nginx 配置、证书管理记录、PHP/Imagick 配置、宝塔计划任务命令。
- 不需要备份 `vendor/`、`node_modules/`、缓存、开发用 `.tools/`、临时上传文件。日志根据审计需求单独保留，避免泄露信息。

备份应存放在 Web 根目录之外，权限仅允许备份用户读取，异地副本加密。数据库转储和 `.env` 不得通过图片域名公开下载。保留至少一个经过恢复验证的历史版本；删除历史原图或永久清空回收站前先取得可恢复备份。

## 一致性备份示例

以下假设库名 `image_vault`、路径 `/www/wwwroot/image-vault`。备份目录必须提前创建在 Web 根目录之外。不要将密码直接写入命令或日志；使用受限的 MySQL option 文件（0600）。

MySQL option 文件格式（真实密码保存在文件中，不提交版本库）：

```ini
[client]
host=127.0.0.1
port=3306
user=image_vault_backup
password=替换为实际密码
```

该账号至少须具备 `SELECT`、`SHOW VIEW`、`TRIGGER` 及实际转储所需权限；`--no-tablespaces` 减少额外权限需求。按照服务器 MySQL 8.0 客户端的实际路径运行。

1. 暂停本项目宝塔清理任务；进入维护模式并确认当前上传已结束。
2. 若不能保证所有浏览器上传/管理员操作已停止，用宝塔暂时停止本站或将整个 server 切到维护响应。仅 Laravel `artisan down` 不阻止 Nginx 静态文件读取，但足以阻止新的应用写入；仍需防止同时运行的 CLI 清理。
3. 使用同一时间点的一组数据库、本地文件与云端对象备份。下列命令只涵盖数据库和本地文件，云端须另用服务商受控备份/复制方案：

```sh
cd /www/wwwroot/image-vault
/www/server/php/84/bin/php artisan down
mysqldump --defaults-extra-file=/secure/image-vault-backup.cnf --single-transaction --quick --no-tablespaces --default-character-set=utf8mb4 image_vault > /secure/backups/vault-YYYYMMDD.sql
tar -czf /secure/backups/vault-YYYYMMDD-files.tar.gz public/media storage/app .env composer.lock
/www/server/php/84/bin/php artisan up
```

4. 恢复本项目清理任务，确认站点正常；保存 SHA-256 校验和、备份时间、应用版本、MySQL/PHP/Imagick 版本及备份命令退出码。

注意：`--single-transaction` 保证 InnoDB 数据库转储的一致读，但不自动同步文件系统。因此维护窗口和暂停清理是数据库/图片一致性的必要条件。命令失败时不要删除旧备份；先解决失败原因并确认应用退出维护模式。

## 隔离恢复

在新的目录、独立 MySQL 数据库和独立测试域名恢复，切勿直接覆盖唯一生产副本。

**云端隔离须单独落实。** 恢复数据库与原 APP_KEY 后，加密配置仍能解密，并继续指向原桶/前缀；更换本地域名和数据库不构成对象存储隔离。没有独立对象副本、隔离凭据、测试桶/前缀及明确操作授权时，禁止运行云写入、存储重试、停用/恢复、复制或清理验证，也不要启用计划任务。密钥解密正常只证明密钥匹配，不能作为云端隔离证据。配置定位字段固定，恢复演练必须在受控离线副本中按验证方案映射到独立副本并核对每图归属与对象键；禁止修改生产配置。开发/自动测试仅使用虚构配置与模拟云存储，不复制真实云配置。只读核对也应避免未经授权连接生产桶。


1. 安装相同 PHP 8.4、兼容 Imagick/WebP 与 MySQL 8.0；恢复对应版本源码并执行 `composer install --no-dev`。
2. 校验备份哈希，解压到新项目目录（归档来源必须可信，解压前检查路径不含绝对路径或 `..`）；保留 `.env` 原始 `APP_KEY`，仅修改测试域名、数据库连接与必要环境项。
3. 创建空库与独立账号，导入 SQL（此操作会写入所指定的目标库，请先复核库名）：

```sh
mysql --defaults-extra-file=/secure/image-vault-restore.cnf image_vault_restore < /secure/backups/vault-YYYYMMDD.sql
```

4. 修复站点用户权限，确保私有目录仍在 `public` 之外；配置 Nginx 只公开合规 WebP。
5. 运行 `php artisan optimize:clear`、`php artisan migrate --force`，确认迁移与恢复代码版本匹配；按需 `php artisan optimize`。**不得为已恢复系统重新运行 `key:generate`**。
6. 暂不启用自动清理，先完成下列验证；防止恢复测试立即删除已超过 30 天的回收站文件。涉及云对象的项目，只有完成上述对象隔离并获授权后才可执行；否则标记“未验证”，不能执行试探性写入。

## 恢复验证记录

至少保存这些证据后，才可将备份标为“恢复验证通过”：

| 检查 | 通过条件 |
| --- | --- |
| 数据总数 | 图片总数、回收站数、分组数与备份前一致 |
| 文件完整性 | 逐条检查公开、停用、预览和原图路径对应实际文件；抽样 SHA-256 一致 |
| 管理员 | 原账号密码可登录；匿名访问后台/原图受保护 |
| 外链 | 活跃图 200 且为 WebP，停用图 404，回收站图在未停用时仍 200 |
| 图片内容 | 抽样照片、透明图、方向图像尺寸/内容/透明正常 |
| 修改与恢复 | 测试副本可重命名、移动分组、停用/恢复且原外链稳定 |
| 上传 | 隔离测试新上传成功，随机新地址、不覆盖旧文件，原图开关正确 |
| 清理 | 在确认范围后手动验证清理命令并确认最近执行状态更新 |
| 容量 | 记录 DB/公开图/原图/回收站与磁盘余量，确认足够运行空间 |

记录日期、环境、版本、执行人、备份标识、结果和差异；不得把本地跑通视为线上灾难恢复已验证。确认恢复可用后再恢复计划任务。若要正式切换域名，另行安排停写窗口、最终增量一致性备份及回滚点。

应用提供 `php artisan vault:audit` 只读核对命令，可用于恢复后的第一步检查。它报告记录对应文件缺失、大小不一致与孤立文件，不会自行删除或修复。进程崩溃或断电后的异常文件须结合备份和日志人工判断，不要直接批量删除。


## 更新内置恢复

1.0.0更新入口额外在 `storage/app/updates/tasks/<任务ID>/backup` 保存更新前程序与完整MySQL表快照，使用私有清单哈希验证。此目录包含敏感业务记录，只允许本站PHP用户读取，不映射公开URL。`storage/app/updates/runtime`为Composer独立恢复执行器；更新失败时保留整个目录。它不会备份或修改媒体，仅适用于不改媒体的发行迁移，不能替代上文整站灾备。仅由原先已登录管理员授予当前浏览器的Cookie进入 `/update-recovery`，每次操作校验独立CSRF。备份验证失败时不得删除日志、伪造备份清单或绕过检查；使用已验证的离线整站备份处理。
