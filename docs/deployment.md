# 宝塔直接部署

目标：PHP 8.4.1+、Laravel 13、MySQL 8.0、Nginx、Imagick/WebP、本地磁盘。无需 Docker、Redis、常驻队列或 Node 开发服务器。下列路径和域名均为模板，请替换为自己的站点；本文不是已完成的线上部署记录。

## 1. 环境与目录

在宝塔安装 Nginx、MySQL 8.0、PHP 8.4.1 或更高补丁版本。PHP CLI 与 FPM 必须使用同一版本及扩展。PHP 必需扩展：`ctype`、`curl`、`dom`/`xml`、`fileinfo`、`filter`、`hash`、`mbstring`、`openssl`、`pcre`、`PDO`、`pdo_mysql`、`session`、`tokenizer`、`exif`、`imagick`；安装/更新依赖另需 `zip`/`unzip`。`gd` 不替代 Imagick。

ImageMagick 必须具有 WebP 编解码支持；安装 Imagick 后重启该版本 FPM，并用同一 CLI 验证：

```sh
/www/server/php/84/bin/php -v
/www/server/php/84/bin/php -r 'echo phpversion("imagick"), "\n"; var_export(Imagick::queryFormats("WEBP"));'
```

公开程序目录示例 `/www/wwwroot/image-vault`，站点运行目录必须设为 **`public`**。页面会自动检测；仅当报告权限失败时修复对应路径，只允许该项目运行用户写入 `storage/`、`bootstrap/cache/`、`public/media/`，不使用 `chmod -R 777`。私有目录必须位于 `public` 之外：

| 路径 | 用途 | 可公开 |
| --- | --- | --- |
| `public/media/YYYY/MM/<32hex>.webp` | 外链图片 | 是，仅严格匹配 WebP |
| `storage/app/previews/` | 后台 WebP 预览 | 否，仅授权控制器 |
| `storage/app/originals/` | 按开关保留的原图 | 否，仅授权下载 |
| `storage/app/disabled/` | 已停用的公开文件 | 否 |
| 临时处理目录（`storage/app` 内） | 上传/转换中间文件 | 否 |

不要执行 Laravel `storage:link`，不要为私有目录配置 Nginx `alias`，不要开放目录列表。

## 2. 上传完整安装包并打开安装页

推荐使用 `release/image-vault-20261028-production.zip`，已经包含 composer.lock 对应生产 vendor 与前端资源，服务器无需 Composer、Node 或终端命令。不要上传本机 `.env`、`.tools`、图片数据或 macOS 扩展。

解压到站点目录，宝塔PHP选择8.4.1+、运行目录 `/public`，在伪静态中粘贴下节片段。直接打开 `/install`：自动检测PHP扩展、所有必需目录的实际创建/写入/读回/改名/删除、原子移动与透明WebP。无需先检查权限，不用生成、读取或输入密钥，不预先复制env、生成APP_KEY或迁移。

必要检查通过后填写独立MySQL8空库、站点地址、唯一管理员并确认。程序自动建立内部随机状态，保留CSRF、限流、文件/MySQL锁，完成后写env与永久安装锁。已有APP_KEY、缓存、非空库和中断日志会阻断重装。管理员密码至少12字符、最多72字节。

仅在页面报告失败时按该项路径在宝塔修复权限/扩展。安装期间项目根目录（public上级）需可原子生成env，私有安装与会话目录由程序尝试创建；目录所有者应为本站PHP用户，禁止chmod777。扩展必须在宝塔安装并重载本站PHP-FPM，不能随ZIP替代。安装完成后可收紧项目根目录写权限，后台对此只作建议。

缺vendor时重新解压完整包；缺启动扩展时/preflight显示修复提示。生产使用HTTPS，APP_KEY须妥善备份，已有系统不可重新生成。

### 保留 CLI 初始化

手工流程只用于全新独立空库：

```sh
cp .env.example .env
# 先安全填写本站数据库、URL等配置；禁止复用其他站点库
/www/server/php/84/bin/php artisan key:generate
/www/server/php/84/bin/php artisan migrate --force
/www/server/php/84/bin/php artisan vault:admin admin@example.com
/www/server/php/84/bin/php artisan optimize
```

`vault:admin` 通过隐藏交互输入密码，无命令行密码参数；唯一管理员创建后写安装锁。若管理员已创建但锁写入失败，修权限后执行 `vault:seal-installation`，不要重复创建账号。旧站补锁也使用该命令；它核对全部迁移及唯一管理员后只写锁，不修改账号/业务数据。已有 APP_KEY、配置缓存、非空库均拒绝网页重装，即使新锁被删除。

`IMAGE_PUBLIC_URL` 可留空使用 APP_URL；单独图片域名须为实际指向本站 WebP 目录的 HTTPS origin。数据库保留相对路径，更换图片域名无需重写记录。

### 中断与失败恢复

安装不是跨 MySQL DDL 与文件系统的整体事务。可捕获失败时恢复原 `.env`，仅补偿本次随机密码哈希匹配的管理员，不删除已经创建的数据表。`storage/app/installation/` 中 `journal.json` 记录阶段和恢复结果，不含数据库/管理员密码；`pending.env` 与 `environment.backup` 包含秘密，只允许服务器管理员读取并纳入受保护备份。失败后网页停止自动重试，不把部分安装标为完成。

先暂停站点写入，备份当前目录和目标库，核对日志目标、迁移表及管理员是否存在。由服务器管理员安全确认 `pending.env` 确实属于本次目标并恢复为运行配置，保留原配置备份。使用正常 `php artisan migrate --force` 补全迁移；仅在确认没有管理员时执行 `vault:admin`，已有唯一管理员则保留。全部迁移和管理员核对后执行 `vault:seal-installation`，再验证登录及环境。不要删除日志/锁来绕过状态检查，不要运行 `migrate:fresh` 或导入覆盖已有业务库。若环境恢复失败，先从受保护备份恢复配置，不能继续在线安装。

## 3. 上传、内存和进程限制

默认应用限制为每批 50 张、单图 20MB，前端逐图发送，不会一次发送整批文件。应用设置可以调整；调大应用限制时必须同步调整 PHP 和 Nginx 限制。

PHP 8.4 示例：

```ini
upload_max_filesize = 21M
post_max_size = 24M
memory_limit = 512M
max_execution_time = 120
max_input_time = 120
```

Nginx `client_max_body_size 24m`。图片压缩前须限制像素数；20MB 的压缩图片解码后内存可能很大。根据实际内存设置 ImageMagick policy 资源上限，并保持 JPEG、PNG、WebP coder 可用，禁用无需的远程 URL/危险 coder（HTTP/HTTPS/MVG/MSL/PS/PDF 等）。同样验证带透明 PNG、方向 JPEG、静态 WebP；GIF、SVG 和动态 WebP 应明确被拒绝。

本应用同步处理低并发上传。无需启动 `queue:work` 或 Horizon。

## 4. 宝塔伪静态与 HTTPS

`deploy/nginx.conf.example` 是完整server参考，不是伪静态；无需替换证书、域名和日志配置。宝塔现有站点选择PHP8.4后保留默认PHP include，在“网站 → 设置 → 伪静态”替换原规则为以下内容，不重复追加：

```nginx
# 粘贴到宝塔：网站 -> 设置 -> 伪静态（替换原伪静态，不要重复追加）。
# 前提：运行目录 /public；宝塔 PHP 版本选择 8.4，保留默认 enable-php-84.conf。
# server 级 return 防护先于任何 PHP/静态正则 location 生效，无需调整 include 顺序。
if ($uri ~* "^/(?:storage|originals|previews|disabled|vendor|app|bootstrap|config|database|resources|routes|tests|deploy|docs|bin)(?:/|$)") {
    return 404;
}
if ($uri ~ "(?:^|/)\.(?!well-known(?:/|$))") {
    return 404;
}
# 只允许 /index.php 进入宝塔现有 PHP handler，阻止其他脚本及 PATH_INFO。
if ($uri ~ "^/(?!index\.php$).*(?i:\.(?:php[0-9]*|phtml|phar))(?:[./]|$)") {
    return 404;
}
# 拒绝所有非规范 media 路径（包括大小写变形），避免被默认静态缓存正则接管。
if ($uri ~ "^(?!/media/[0-9]{4}/(?:0[1-9]|1[0-2])/[a-f0-9]{32}\.webp$)(?i:/media)(?:/|$)") {
    return 404;
}
location ^~ /media/ {
    try_files $uri =404;
    open_file_cache off;
    types { image/webp webp; }
    default_type image/webp;
    expires off;
    add_header Cache-Control "public, max-age=0, must-revalidate" always;
    add_header X-Content-Type-Options nosniff always;
    etag on;
}
location / {
    try_files $uri $uri/ /index.php?$query_string;
}
```

片段使用server级return先拦截私有目录、隐藏文件和非index脚本，能覆盖先出现的默认PHP/静态缓存正则；^~ /media/使公开WebP不进入宝塔长期图片缓存。停用图片时原文件移走，源站下一次请求404；恢复原路径后200。私有目录不映射，media只接受规范年月/32位hex.webp。

如果主配置已经自定义`location /`或`location ^~ /media/`，需移除对应重复location再保存。不要删除默认PHP include。运行目录必须是public，单独try_files不保护错误Web根或缺失PHP handler。宝塔保存应通过Nginx语法检测；HTTPS证书仍由现有站点配置。第三方缓存或保存副本无法由源站撤回；自定义CDN/open_file_cache需另核实失效策略。

## 5. 定时清理

宝塔计划任务创建 Shell 任务，每小时执行一次（不要设置网页访问型 cron）：

```sh
cd /www/wwwroot/image-vault && /www/server/php/84/bin/php artisan vault:cleanup >> storage/logs/cleanup.log 2>&1
```

命令自动清理进入回收站超过 30 天的图片及对应文件，并处理过期临时文件、更新最近执行状态。回收站中的图片在到期永久清理前仍可通过外链访问；立即撤下须使用“停用链接”。原图开关仅影响未来上传，历史原图必须使用后台独立清理操作；确认操作范围包含回收站记录。

将任务运行用户设为站点用户，确认能写入全部存储目录。首次手动运行命令，并在“设置 / 运行状态”确认最近执行时间更新；日志设轮转。不要同时为同一项目设置重复清理任务。

## 6. 上线验收

1. 未登录访问 `/library`、`/settings`、预览和原图下载应转登录；`/register` 返回 404。
2. 登录后上传 JPEG/透明 PNG/静态 WebP，确认公开地址为 HTTPS WebP，尺寸/体积及 Markdown/HTML 链接正确；原图保留默认关闭。
3. 启用未来原图保留后另上传一张，匿名访问下载路由仍不可读取；不得在 public 找到原始格式。
4. 匿名请求已发布 WebP 返回 200；移入回收站仍为 200；停用后新请求 404，恢复后 200；永久删除后 404。
5. 访问 `/media/test.php`、`/media/test.png`、`/storage/…`、`/.env`、`/vendor/…` 不得返回文件内容，上传目录中的 PHP 不得执行。
6. 手动执行清理命令，检查后台状态；执行一次离线备份并在隔离环境恢复验证。
7. 1440px 桌面与 390px 手机检查上传、库筛选、批量操作、回收站、改密码；查看 PHP/Nginx 错误日志。

以上是部署者必须在真实目标环境完成的验收清单。本地 PHP 开发服务器的检查不能证明宝塔 Nginx 静态规则已生效。

## 7. 一致性与核对

`storage/app/tmp`、`public/media` 和私有图片目录应位于同一文件系统。发布使用写完并验证的暂存文件、发布锁及原子重命名；跨文件系统会被拒绝。可捕获的数据库或文件异常会清理新文件或恢复已移动文件。每张图片独立处理；批量中途失败会明确报告已完成数量并停止后续操作，不宣称整批跨文件事务。

维护或恢复后运行 `php artisan vault:audit`，核对记录对应文件及孤立文件。该命令只读；发现问题时先保留备份及日志，再处理异常。断电/SIGKILL等全部崩溃窗口尚未演练。

模板使用 `http2 on`，要求 Nginx 1.25.1 或更高；旧版本需要按其语法调整并通过 `nginx -t`。本机开发测试的 PHP/Imagick 运行器不属于 Linux 部署产物。

正式程序版本从 **1.0.0** 开始；schema 版本另存为已执行迁移清单。未带版本记录的既有安装仅在迁移、表和字段清单、唯一管理员符合 `legacy-20261028` 时允许接入。它在更新界面显示内部程序基线 `0.0.0`，这不代表曾发布过 0.0.0。

本次交付三种包，不能混用：

- `image-vault-20261028-update-v1-final-production.zip`：全新空库安装，包含生产 vendor。
- `image-vault-1.0.0-legacy-transition.zip`：仅为上述既有已安装版本首次接入更新入口。先备份站点程序、配置、图片和数据库，在宝塔解压后将 `image-vault` 内的文件覆盖到既有项目根目录。保留原 `.env`、全部 `storage`、`public/media`，不重新安装，不执行 `key:generate`，不要求空库。本包不带这些运行数据。首次覆盖仍须由宝塔处理，无法由旧版不存在的更新功能自行安装。
- `image-vault-1.0.0-legacy-signed-update.zip`：过渡接入后在后台“系统更新”上传。仅接受明确识别的 legacy 基线，目标 1.0.0；已经是 1.0.0 的站点会拒绝同版本重装。本次不发布测试使用的伪造高版本包。

上传时先验签、核对兼容范围、PHP CLI/扩展、MySQL 8 InnoDB、程序权限和磁盘。1.0.2 安装后的后续更新确认后保留在 `/updates`，后台通过受保护接口逐阶段完成完整数据库与将替换程序备份、程序替换、全部缺失迁移、缓存清理、健康检查。恢复入口仍经现有 `index.php` 与伪静态进入，在 Composer 前分流，使用更新前冻结的独立执行器。仅已认证管理员能授予当前浏览器七天的 HttpOnly 恢复 Cookie；持久状态只保存其哈希。不要清除此 Cookie、切换浏览器或删除私有 updates 目录。Cookie 丢失或过期时，恢复入口支持使用本次更新前的管理员邮箱和密码重新认证；只有正确密码才能重新取得授权，登录有独立 CSRF 与限速。服务器仅冻结既有口令哈希，不保存明文。不能提供该密码时须使用受保护离线备份恢复。

更新期间统一写锁排空正常后台请求与 `vault:cleanup`，后续后台访问停止；Nginx 直接提供的已有 WebP 路径保持可读。不得同时执行外部 SQL、手工 Artisan 迁移或其他绕过本程序锁的写入。本协议限定发行迁移仅修改数据库，不移动、改写或删除媒体；有媒体转换需求的版本不得使用此协议发布。备份包含程序与数据库，日常图片灾备仍按“备份与恢复”执行。

兼容范围由固定公钥签名清单声明，仅支持同一程序大版本内明确列出的起止范围。每个完整目标包含所有历史迁移，跳过中间程序版本时按顺序补执行缺失迁移。不承诺任意跨版、跨大版本、降级或未知基线。本站固定发行公钥不能由上传包替换；签名私钥只留发行方受限本机目录，绝不上传服务器或加入发布包。

需要 PHP ZIP、OpenSSL、pdo_mysql、Imagick 和可用 `proc_open`、同版本 PHP CLI；不可用时阻断。程序目录及其文件须允许本站 PHP 用户进行原子替换；普通文件 0644、程序目录 0755、storage 私有目录 0700，不使用 777。数据库包含视图、非 InnoDB 表、触发器、例程、事件或生成列时阻断。目标数据库账号须直接具备该库的 ALL PRIVILEGES，以证明完整对象可见性及恢复权限；等效角色或分散授权本版保守拒绝。数据库逻辑备份有 512 MiB 上限，原始单行超过 12 MiB 会在备份前阻断；恢复校验使用 0600 临时副本，系统临时目录还须容纳一份数据库备份；单阶段备份与恢复仍是一个请求，大库或严格 FPM/代理时限须先在同配置测试站演练。本地验证不证明真实宝塔时限或权限配置满足要求。

MySQL DDL 可能已生效而 migration 记录未写入。迁移请求中断后不自动重复迁移，页面保留维护状态，选择“恢复更新前版本”。恢复在任何删除数据前验证全部程序与数据库备份清单、文件哈希和行数；损坏、不完整或目标不符会保持维护并拒绝破坏性恢复。恢复可重试，完成后健康检查并使旧数据库会话失效，重新登录。更新成功后不提供在线回退，以免覆盖更新后的新数据。私有备份包含账号哈希和业务数据，磁盘容量与后续离线保留/清理由管理员负责。

### 1.1.0 多存储（2026-10-29）

新站使用 `image-vault-20261029-update-v1-1-0-production.zip`；正式 1.0.0、1.0.1、1.0.2 使用 `image-vault-1.1.0-signed-update.zip`，不新增过渡包。旧无版本站须先按原 1.0.0 流程接入。升级到 1.1.0 的这一次由原版本执行器处理；升级前独立备份数据库、原 `.env` 与全部媒体。

支持本地、腾讯 COS、阿里 OSS、通用 S3 的多份配置，可设置默认目标并在每批上传时选择。默认切换仅影响新上传；每图固定原存储归属。历史图片仅登记为本地，不迁移文件，原 `/media/` 外链保持。云端仅保存公开 WebP；私有预览、可选原图和停用完整副本仍在本站，必须纳入本地灾备。配置被历史图片、回收站或待完成操作引用时不能删除，桶、地域、Endpoint、前缀和公开域名不能原地修改。

第一阶段仅支持从未开启版本控制且无对象锁/保留策略的普通桶，不支持历史迁移、自动故障切换或跨桶同步。桶需允许对象 Put/Get/Head/Copy/Delete，并能查询版本与对象锁/保留状态：S3/COS 为 GetBucketVersioning、GetObjectLockConfiguration（COS 按兼容接口实际支持情况核验），OSS 为 GetBucketVersioning、GetBucketWorm。不同服务商 IAM 动作名与权限组合需按其文档配置；不要为通过测试授予整账号管理权限。无法确认桶状态时拒绝写入。配置后的随机测试仅操作前缀下 `_checks/` 路径；匿名公开访问须单独通过，通用 S3 必须逐项验证。

Endpoint/公开域名使用公网 HTTPS；COS/OSS 使用地域对应官方公网 Endpoint。Web 与同版本 PHP CLI 均需 cURL、SimpleXML 和 `dns_get_record`（另有安装页列出的原有扩展与进程函数）。SDK 固定为 AWS 3.402.2、OSS 2.7.3，生产依赖共 82 个。

云图停用先持久保存并校验完整 WebP，再删除源站对象；恢复时重新上传。CDN、浏览器或第三方副本无法立即撤回，须另行清缓存；云端软删除仍保留外链，计划任务到期才清除。远端结果未知时保留操作意图与安全副本，在设置或清理计划重试，不要手工删记录或私有副本。

密钥由本站 APP_KEY 加密且不回显。灾备必须同时保存数据库、原 APP_KEY（轮换时包括需要的旧密钥）及私有媒体，不得重新生成 APP_KEY。发布包不含凭据或业务媒体。发布验收使用隔离数据库和模拟云存储；真实 COS/OSS/S3 桶、CDN、Linux 宝塔 FPM/CLI/权限与 OPcache 尚未实机验收，首次启用前须在测试桶验证。

升级前须在宝塔分别核对 Web 与实际同版本 PHP CLI 的 cURL、SimpleXML 和 `dns_get_record`。**1.0.0–1.0.2 的旧冻结更新器不会完整自动检测这些新增云存储能力**；签名清单只声明 PHP 最低版本，不能代替上述人工能力核对。缺少能力时先修复再上传更新包；不得通过放宽旧协议或跳过检测来安装。

### 1.1.1 更新任务清理（2026-10-29）

已有正式 1.1.0 在后台“系统更新”上传 `image-vault-1.1.1-signed-update.zip`；本包仅接受 1.1.0，不支持重复安装、降级或其他来源。新站使用 `image-vault-20261029-update-v1-1-1-production.zip`。数据库迁移清单仍为八项；不搬迁媒体、不改依赖、不重建 APP_KEY。旧发行包保留，不将 1.1.1 内容覆盖到 1.1.0 文件名下。

1.1.1 更新器先校验已安装文件与签名清单一致、旧托管文件已移除、迁移记录完整、数据库身份及 Laravel 启动正常，检查业务表、存储配置解密与上传页渲染。版本和 complete 状态可靠保存后，立即删除该成功任务的 payload、程序备份和数据库备份，不保留七天或最近一份；保留轻量成功凭据、日志及清理结果。清理失败不改变成功状态；运行中、失败、迁移中断、恢复中任务及没有成功凭据的历史目录禁止自动清理。正常页面读取状态不会执行删除。

**从 1.1.0 上传本包的这一次仍由原 1.1.0 冻结更新器完成，成功响应时不会立即执行新清理。** 安装完成后，在项目根目录使用本站同版本 PHP 执行 `php artisan vault:cleanup --updates-only --no-interaction`。该选项只重新核验当前 1.1.0 → 1.1.1 成功任务；文件、迁移、环境、数据库结构、启动与保存的版本全部匹配后，保存独立成功凭据，再清理这一个任务。核验失败保留备份并记录待重试；历史五组任务不会因本次安装而自动判定成功。由 1.1.1 更新器发起的后续更新在成功落盘后立即清理。

发布包不会自动创建维护计划。管理员可自行配置上述仅更新清理命令用于后续重试；不要假定正式站已配置。未加 `--updates-only` 的既有 `vault:cleanup` 同时永久清理回收站满 30 天的图片并重试远端待办，应按原维护安排使用，不能把它当作仅清升级备份的命令。

上传前确认宝塔防篡改允许本站 PHP 对程序托管文件执行 chmod、原子 rename 与删除，并允许写入 storage、bootstrap/cache；仅放行日常 storage 目录不能代替程序更新权限。不要通过 chmod 777 规避。升级前仍须独立保存站点灾备；更新任务备份成功后会被清理，不能用作长期备份。本地验收不等同于目标宝塔 FPM、OPcache 或防篡改验收。


### 1.1.2 批量上传与来源导出（2026-10-29）

正式 1.1.1 使用 `image-vault-1.1.2-signed-update.zip`，兼容范围严格为 1.1.1；新站完整包为 `image-vault-20261029-update-v1-1-2-production.zip`。八项数据库迁移和锁定依赖不变。更新包含 `public/assets/upload.js`，上传页先加载它，再加载 `app.js`，两者均按内容哈希更新缓存地址。
